# Documentation map

Read these files in this order when describing the current project:

1. The repository `README.md` for scope, local startup and verification.
2. `docs/IMPROVEMENT_PROGRESS.md` for delivered work and approval boundaries.
3. `docs/ARCHITECTURE.md` for the implementation shape.
4. `docs/API.md` and `docs/openapi.json` for the generated API surface.
5. `docs/DEPLOYMENT.md` for local Compose and hosted prerequisites.
6. `docs/DEMO_SCRIPT.md` for the seeded synthetic walkthrough.

`backend-specification.md` and `frontend-specification.md` are retained as
design references. Their status banners mean they must not be used to infer
that a planned technology or workflow is implemented. Code and the documents
above are authoritative.
